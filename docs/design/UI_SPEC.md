# UI 규격서 v2 (라이트) — 쉼표 (Every Moment of Pause)

이 문서와 `(삭제) mockups/*.png`(17장, 한눈에 보기는 `(삭제) mockups/overview.png`)가 UI의 기준이다. `ui_design.png`(다른 AI가 만든 어두운 시안)는 아이디어 참고용일 뿐 기준이 아니다(§8). 화면을 만들거나 고칠 때는 항상 해당 시안 PNG를 먼저 열어 보고, 구현 후 에뮬레이터 스크린샷과 나란히 비교한다. 값이 시안 HTML(`(삭제) mockups/mockups.html`)과 다르면 HTML의 CSS 값이 우선이다.

## 1. 콘셉트

**여정은 문장이고, 휴식은 쉼표다.** 경로 위에 놓인 쉼표 기호가 앱의 시그니처다.

- 쉼표 기호는 이 앱에서 "휴식 지점"을 뜻하는 유일한 기호다. 장식으로 쓰지 않는다.
- 화면마다 **가장 중요한 숫자 하나**를 가장 크게 둔다(주행: 다음 쉼표까지 분, 정차: 충전 완료까지 분, 파워냅: 남은 시간).
- 나머지 요소는 조용하게 둔다. 강조색은 한 화면에 한 곳만 쓴다(주 버튼 또는 다음 쉼표).
- 런처(Pleos Connect)가 밝은 회색 톤이므로 기본은 라이트 테마다. 파워냅만 어두운 난로 테마로 바뀐다.

규칙

### 2.2 글꼴 (`ui/theme/Type.kt`)

- 글꼴: **Pretendard**(OFL). `res/font/`에 Regular·SemiBold·Bold·ExtraBold·Light를 넣고 `licenses/Pretendard-OFL.txt`를 함께 둔다. 받을 수 없으면 시스템 기본(Noto Sans CJK)으로 대체하고 크기·굵기는 그대로 유지.
- 숫자는 항상 고정폭 숫자(`fontFeatureSettings = "tnum"`), 큰 숫자는 자간 -0.05em.
- 단위: Pleos Connect 화면은 160dpi라서 1dp = 1px. 시안 px 값을 그대로 dp/sp로 쓴다.

| 스타일 | 크기 | 굵기 | 자간 | 용도 |
| --- | --- | --- | --- | --- |
| `display` | 200sp (1/2 창 180sp) | ExtraBold 800 | -0.05em | 다음 쉼표까지 분 |
| `displayUnit` | 72sp | Bold 700 | -0.02em | "분" |
| `clock` | 220sp | Light 300 | -0.04em | 파워냅 남은 시간 |
| `headline` | 64sp | ExtraBold | -0.03em | 휴게소 이름 |
| `title` | 40sp | Bold | -0.02em | 카드 제목 |
| `button` | 36sp | Bold | 0 | 주 버튼 |
| `body` | 28sp | Regular | 0 | 본문, 줄간격 1.45 |
| `label` | 26sp | SemiBold | 0 | 칩, 보조 정보 |
| `caption` | 24sp | Regular | 0 | 앱바 메타, 경로 라벨 |

- 28sp 미만은 정차 화면에서만 쓴다. 주행 화면의 최소 글자는 24sp(경로 라벨)이다.
- 대문자 라벨, 한 단어만 색 바꾸기 같은 장식은 쓰지 않는다.

## 4. 화면별 규격

### 4.1 주행 글랜스 — `(삭제) mockups/01-drive.png` (AppMode = DRIVING)
- 2단: 왼쪽 큰 정보, 오른쪽 500dp 폭 카드 2개(피로, 가족). 하단에 `JourneyLine`.
- 왼쪽 위에서 아래로: "다음 쉼표까지"(32sp) → 분(display) → 휴게소 이름(headline, 한 줄, 넘치면 "휴게소" 뒤 방향 생략) → 이유 칩 최대 3개 → 버튼 행.
- 버튼 행: `여기서 쉴게요`(Primary) + `다음 곳으로`(Ghost) + `VoiceHint`. 버튼 2개를 넘기지 않는다.
- **RESTRICTED일 때:** 오른쪽 카드 2개를 숨기고, 가족 카드의 가장 급한 한 줄만 칩으로 내린다. 글자 수는 카드당 2줄 이하.
- 제안이 없을 때: 분 자리에 "다음 쉼표"까지 거리 대신 "지금은 편안해요"(headline) + 다음 예정 쉼표 시각. 버튼 없음.

### 4.2 출발 준비 — `(삭제) mockups/02-prepare.png` (PREPARE)
- 왼쪽: 멤버 카드(타일 4칸, 168dp 높이, 아바타 64dp + 이름, 선택 시 `restSoft` + 오른쪽 위 체크) → 수면 질문(4~8시간+ 알약형 버튼 112dp) → "피로가 오르기 전에 먼저 알려 주기" 토글 행.
- 오른쪽: 오늘의 쉼표 계획(휴게소, 편의시설, 예상 시각) + 미리보기 `JourneyLine` + 근거 한 줄 → 하단 `이대로 출발`(Primary, 넓게) + `바꾸기`(Quiet).
- 수면 질문은 음성으로도 답할 수 있다("다섯 시간"). 건너뛰면 7시간으로 계산하고 그 사실을 한 줄로 표시.

### 4.3 멈춤 큐레이터 — `(삭제) mockups/03-pause.png` (PAUSE, 충전 중)
- 위: "충전이 끝날 때까지" + 분(180sp) / 오른쪽 배터리 막대(현재→목표, 완료 예상 시각).
- 오른쪽 위: 배터리 카드(현재 %, 목표 %, 막대에 목표 위치 표시선, 충전 출력 kW, 완료 예상 시각).
- 가운데: `ActivityRow` 3줄(높이 172dp, 아이콘 원 96dp, 대상·활동명·설명 한 줄, 오른쪽 버튼). 추천 행은 4dp `rest` 안쪽 테두리 + "지금 가장 필요해요" 태그. 순서는 운전자 → 아이 → 반려동물, 동승자가 없으면 "업무 집중 15분"·"스트레칭 5분".
- 아래: 정차 타임라인(도착 시각 → 지금 → 기상 알림 → 충전 완료, 각 점 아래 시각과 라벨).
- 충전이 아닌 정차: 위 숫자를 "15분 쉬어 가요"(사용자가 10/15/20분 선택)로 바꾼다.

### 4.4 파워냅 — `(삭제) mockups/04-nap.png` (PAUSE, 파워냅 활성)
- 배경: `night` → 아래쪽 따뜻한 빛(radial). 화면 밝기 낮춤 요청(가능하면 시스템 API, 불가하면 앱 내 어둡게).
- 파워냅만 **어두운 테마 예외**: 잠든 차 안에서 밝은 화면은 휴식을 방해하기 때문. 라이트 테마 사용자도 이 화면만 어둡다.
- 가운데 위: 원형 진행 링(지름 560dp, 두께 16dp, `ember`) 안에 "남은 시간" + 시간(150sp Light). 아래 "충전이 끝나기 2분 전, HH:MM에 깨워 드릴게요".
- 아래: `Fireplace` + 버튼 3개(`지금 일어나기` ember / `10분 더` / `장작 소리 끄기`). 버튼 높이 112dp.
- 기상: 2분 전부터 화면 밝기·소리 단계적 상승 → 알림 음성 → 1분 무응답 시 반복.
- DriveState가 DRIVING/RESTRICTED가 되면 즉시 종료하고 주행 글랜스로.

### 4.5 여행 리포트 — `(삭제) mockups/05-report.png` (ARRIVED)

- 실패: 마이크 아이콘 + "잘 듣지 못했어요 / 버튼으로 골라 주세요" + 버튼 2개(같은 동작). 실패는 1번만 재시도하고 이후 버튼만.

### 4.10 오프라인 — `(삭제) mockups/12-offline.png`
- 앱바 아래 `sunk` 배너(높이 72dp): "인터넷이 끊겨 저장된 휴게소 정보로 안내하고 있어요". 나머지는 평소와 같다(모달 금지).
- 피로 카드 설명을 "피로 계산은 인터넷 없이도 계속돼요"로 바꾼다.

### 4.11 첫 실행 온보딩 — `(삭제) mockups/13-onboard-1.png` ~ `15-onboard-3.png` (PARKED에서만)
- 2단: 왼쪽 단계 표시(막대 3개) + 제목(72sp) + 설명 + 버튼, 오른쪽 그림 영역.
- 1단계: 콘셉트("여정은 문장이고, 휴식은 쉼표예요"), 경로 위 쉼표 일러스트.
- 2단계: 동승자 등록(어른·아이 나이·반려동물 타일 2×2), "이 정보는 이 차에만 저장돼요".
- 3단계: 마이크 권한 이유("제안 직후 8초만 듣고, 녹음은 저장하지 않아요") + "마이크 허용하고 시작" / "버튼으로만 쓸게요".
- 주행이 시작되면 온보딩을 중단하고 다음 정차 때 이어서 보여준다.

### 4.12 설정 — `(삭제) mockups/16-settings.png` (PARKED에서만)
- 왼쪽 메뉴 420dp(제안과 알림 / 함께 타는 가족 / 이 차에서 쓰는 신호 / 개인정보와 데이터 / 앱 정보), 오른쪽 내용.
- 제안 시점 세그먼트(빠르게/보통/여유 있게) + 현재 값 설명, 토글 행(음성 제안, "아직 멀었어?" 답하기, 장작 소리), 신호 목록(사용 중 / 이 차는 지원 안 함).
- 주행 중 진입 시: "정차하면 설정할 수 있어요" 한 줄 화면.

### 4.13 앱 아이콘 — `(삭제) mockups/17-icon.png`

## 5. 반응형 기준

| 앱 창 폭 | 레이아웃 |
| --- | --- |
| ≥ 1200dp | 시안 그대로(2단) |
| 700~1199dp | 1/2 창 레이아웃 |
| < 700dp | 최소 레이아웃(`07-third.png`: 숫자·이름·버튼 1개, 피로는 앱바 알약으로) |

`BoxWithConstraints` 또는 `WindowSizeClass`로 분기한다. 세 폭 모두에서 글자가 잘리거나 두 줄이 되면 안 된다.

## 6. 문구 원칙

- 존댓말, 짧은 평서문. "~해요", "~할게요". 버튼은 실제로 일어나는 일을 말한다(`여기서 쉴게요` → 누르면 경유지 추가 → 안내 "경로에 안성휴게소를 넣었어요").
- 오류는 무엇이 안 됐고 어떻게 되는지 말한다. 예: "지금은 휴게소 정보를 새로 받지 못해 저장된 정보로 안내해요."
- 동승자 이름은 사용자가 입력한 이름을 그대로 쓴다(시안의 "지우", "콩이"는 예시).

## 7. 구현 후 검증 루프 (매 화면 필수)

1. 시뮬레이터로 해당 상태를 만든다(예: `seoul-busan-family`를 01:40 지점으로 점프).
2. `adb exec-out screencap -p > artifacts/ui/<화면>_<폭>.png`로 캡처한다. 1/2 창은 앱 창 크기를 바꾸거나 디버그 플래그로 강제한다.
3. 캡처와 `(삭제) mockups/<화면>.png`를 둘 다 열어 비교하고, 차이를 **정렬·위계·대비·여백·글자 넘침·터치 영역** 6개 항목으로 적는다.
4. 차이를 고치고 다시 캡처한다. 6개 항목 모두 "차이 없음 또는 의도된 차이"가 될 때까지 최대 3회 반복한다.
5. 최종 캡처를 `artifacts/ui/final/`에 남긴다(README와 시연 영상에 사용).
